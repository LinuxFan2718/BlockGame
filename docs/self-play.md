# Comparing random-opponent PPO, self-play PPO, and search-guided learning

Read the [protocol](self-play-protocol.md) for the budgets and success criteria
recorded before the experiment. The completed local comparison is saved under
`runs/self-play-study`, including `report.md`, `comparison.json`, and a plot.
The [results discussion](self-play-results.md) explains the passing checkpoints,
the failed PPO self-play comparison, and why the last checkpoint and added search
were not always improvements.

## Run or inspect the experiment

```sh
# New directory, three initializations, and three arms. One CPU thread per worker.
uv run blokus-rl experiment --out runs/my-self-play-study --workers 3

# A small integration check rather than a meaningful training budget.
uv run blokus-rl experiment --out runs/small-study --seeds 42 \
  --updates 2 --episodes-per-update 4 --search-simulations 4 --audit-every 1

# Exact evaluation of an existing raw network.
uv run blokus-rl audit runs/ppo-demo/model.pt

# Raw policy versus the same weights with deterministic search.
uv run blokus-rl audit runs/self-play-study/alphazero-seed-42/best.pt
uv run blokus-rl audit runs/self-play-study/alphazero-seed-42/best.pt --search-simulations 32

# Play either version. The search flag is an explicit deployment choice.
uv run blokus-rl play runs/self-play-study/alphazero-seed-42/best.pt
uv run blokus-rl play runs/self-play-study/alphazero-seed-42/best.pt --search-simulations 32
```

Each run saves both `best.pt`, selected using the declared audit criterion, and
`final.pt`, the weights at the end of the fixed training budget. Earlier results
and baseline models are preserved. The JSON report includes all seeds, both seats,
untrained search, the final and selected checkpoints, and frozen reference opponents.

## What changes in PPO self-play?

The model, reward, PPO loss, and optimizer settings stay the same. The learner
still alternates X/O and uses the decision-to-decision environment adapter.
Only the opponent-selection mechanism changes:

- At the start of each episode, select the current policy with probability 0.8,
  or an immutable earlier snapshot with probability 0.2.
- Keep that opponent for the whole episode, including any opening move.
- Both learner and opponent sample legal actions. Only the learner's decisions
  are recorded for that game's PPO update.
- Freeze all weights during collection. Perform PPO optimization afterward.
- Save an opponent snapshot every ten updates. The archived models have gradients
  disabled and do not change when the current model is optimized.

The same neural policy may control both players during collection, but their
observations and rewards are always encoded from their own perspectives.

This is one specific small self-play curriculum. It can fail to cover important
positions or forget responses to unfamiliar play. Its effectiveness is a measured
question; the presence of self-play is not itself evidence that learning improved.

## What changes in the AlphaZero-style arm?

[`search.py`](../python/blokus_rl/search.py) implements PUCT-guided MCTS with a
small budget of 32 simulations per move. The network supplies legal-action priors
and predicted leaf values. Terminal states use actual game rewards. Player
perspectives change sign as the search alternates turns.

For each training move, the search's visit counts become a target distribution.
A move is sampled from that distribution. After the game ends, every recorded
position gets the outcome from the player-to-move's perspective. The policy head
learns with cross-entropy; the value head learns with mean squared error. No PPO
loss is used for this arm. Root noise is enabled during training, disabled during
evaluation and human play.

The current network's predictions are frozen for each collection batch. Both
players' positions provide training examples. Thus equal numbers of games give
this arm more training positions and more optimizer work than one-learner PPO,
in addition to the cost of search. The resource table makes that difference explicit.

All transitions come from a graph generated by replaying Rust moves. The graph
contains rules and outcomes, not precomputed optimal strategy. Search and collection
never call minimax; a test makes the minimax evaluator raise an error if training
tries to consult it.

## What exactly does the certificate establish?

[`audit.py`](../python/blokus_rl/audit.py) builds all 5,478 reachable game positions
using the Rust engine. For each fixed greedy policy, it enumerates every possible
opponent response from the empty board, separately as X and O. A nonzero count of
losing terminal sequences disproves the never-lose claim and supplies a replayable
counterexample. Zero losing sequences in both seats proves the claim for that
starting condition and policy.

This is stronger than playing a large sample of games. It also examines more
opponent behaviors than the perfect-opponent benchmark, which only selects among
minimax-optimal moves. An opponent can sometimes exploit a flawed learned policy
by making a move that would be unsound against an optimal defender.

The proof covers deterministic greedy inference, or the explicitly tested
deterministic search settings. It does not cover sampling from the policy's
softmax distribution. It also does not claim that the model chooses an optimal
move in every arbitrary midgame position. Those off-trajectory action errors are
reported separately.

The never-lose check counts discrete paths; its conclusion does not depend on a
floating-point probability threshold. Reported win/draw/loss probabilities are
calculated by summing the appropriately weighted branches. They are computed
probabilities, with ordinary numerical precision, rather than Monte Carlo estimates.

Minimax is used to evaluate performance and select checkpoints. It never supplies
the gradient-training labels, opponent actions, or additional rewards. This
distinction matters when interpreting the experiment as learning from self-play.

## Reading a negative result

If self-play has worse perfect-opponent results than the matched control, that
is a regression under the declared experiment. It does not establish that all
self-play curricula or PPO implementations fail. More training, different
opponent mixtures, or other learning settings would be new experiments.

If adding search helps before any learning, some performance comes from planning
itself. If trained search improves further, learning made those predictions more
useful to planning. If search passes the certificate while the raw network fails,
the deployed network-plus-search agent is certified, and the raw network remains
imperfect. The results keep those claims separate.
